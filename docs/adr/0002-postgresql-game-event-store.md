# PostgreSQL game event store

Scorekeepr stores all **Game Events** in a single append-only PostgreSQL `game_events` table. The event envelope uses structured relational columns for identity, game ownership, type, recorded/effective sequence, timestamps, user attribution, and correction relationships, while event-specific bodies are stored as validated JSONB payloads. This was chosen over a specialized event store, document database, or fully normalized event tables because replay requires one ordered stream per game, PostgreSQL fits the rest of the platform data, JSONB gives payload flexibility while the event model evolves, and relational columns preserve the invariants needed for ordering, correction, indexing, and referential integrity.

`recorded_sequence` is assigned under database protection, not by the client, and is unique per game. Replacement events may share the replaced event's `effective_sequence`, so effective sequence is not globally unique within a game. Correction and void relationships are stored in structured nullable columns rather than only inside payload JSONB. Production should enforce append-only behavior at the database level so scoring history is changed through new **Game Events**, not updates or deletes.
